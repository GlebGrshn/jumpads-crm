# Jumpads CRM

Node.js 24+, SQLite, HTML/CSS/JS. Внешних runtime-зависимостей нет.

## Запуск и первый вход

```powershell
node scripts/setup.mjs
npm start
```

В текущем окружении приложение работает на **http://127.0.0.1:3010**. Порт указан в `.env`; при новом запуске setup по умолчанию использует 3000. На странице выберите **Регистрация**, задайте юзернейм и пароль. Старый общий `CRM_PASSWORD` больше не используется. Первый зарегистрированный пользователь становится администратором. Старые cookie автоматически перестают действовать после обновления.

Юзернейм: 3–32 латинские буквы, цифры или `_`, без учёта регистра. Пароль: 8–128 символов. Пароли хешируются через scrypt с индивидуальной солью. Сессии действуют 12 часов, хранятся на сервере и отзываются при выходе.

## Возможности

- **Лиды:** ручное создание и редактирование, компания, контакт, запрос, сумма сделки, ответственный, заметки, теги, поиск, фильтры, история действий, архив/восстановление.
- **Защита от дублей:** нормализованный контакт (включая форматы телефона и t.me/@username) или совпадение имени и запроса вызывает подтверждение. Отказ сохраняет форму и не создаёт лид. Подтверждение разрешает намеренный дубль. Повтор одного и того же запроса с ключом операции возвращает уже созданную запись.
- **Воронка:** Новый → В работе → Предложение → Сделка → Оплачено / Закрыт. Этап «Оплачено» доступен только при подтверждённом счёте Т-Банка. Изменение этапа через список на карточке; число и сумма лидов по колонкам. Архивные лиды исключены.
- **Задачи:** исполнитель, связанный лид, описание, срок, приоритет, статус, отдельное время напоминания. Фильтры: мои, все, поставленные мной; незавершённые, просроченные, выполненные.
- **Напоминания:** уведомления исполнителю сохраняются в SQLite; сервер проверяет их каждые 15 секунд. Просроченные напоминания появляются после перезапуска. Повторная проверка не дублирует уведомление. При выполнении задачи или смене срока/исполнителя старые уведомления отмечаются прочитанными. Браузерные уведомления включаются кнопкой в профиле и работают при открытой странице и разрешении браузера. Web Push, email и уведомлений о задачах в Telegram пока нет.
- **Мессенджер:** общий чат команды, личные диалоги сотрудников и текстовые диалоги клиентов через Telegram-бота. Личные сообщения доступны только отправителю и получателю, включая запрет доступа посторонним администраторам. Для каждого Telegram-сообщения виден статус: в очереди, отправлено, входящее или не доставлено.
- **Автообновление:** каждые 5 секунд; формы не перезаписываются фоновым обновлением. Напоминания проверяются и при открытой форме.

## Роли и тестовый выбор

| Возможность | Администратор | Менеджер | Наблюдатель |
|---|---|---|---|
| Просмотр лидов, задач, общего чата и Telegram | Да | Да | Да |
| Создание и изменение лидов | Да | Да | Нет |
| Архив и восстановление лидов | Да | Нет | Нет |
| Создание задач | Да | Да | Нет |
| Изменение задач | Любых | Созданных им или назначенных ему | Нет |
| Отправка сообщений | Да | Да | Нет |
| Назначение ролей другим | Да | Нет | Нет |
| Чтение чужих личных диалогов | Нет | Нет | Нет |

Права проверяются сервером, а не только скрытием кнопок. Все пользователи входят в одно рабочее пространство.

`TEST_ROLE_SELECTION=true` включает свободный выбор собственной роли при регистрации и в разделе **Команда и роли**. В интерфейсе видна пометка тестового режима. Первый аккаунт получает администратора, затем тоже может выбрать любую роль. В текущем локальном окружении этот режим включён по просьбе пользователя.

Для обычного использования установите `TEST_ROLE_SELECTION=false`: новые пользователи становятся менеджерами, роли меняет администратор, убрать последнего администратора нельзя. Регистрация остаётся открытой; эта версия рассчитана на тестовое рабочее пространство. Инвайты и одобрение новых участников пока не реализованы.

## Telegram

Два бота из @BotFather, токены копируются целиком (`цифры:секрет`). После правки `.env` контейнер нужно пересоздать (`python tools/crm_tunnel.py deploy`): Docker читает `.env` только при создании. Без токенов остальные функции CRM работают.

**Клиентский бот** (`CLIENT_TELEGRAM_BOT_TOKEN`, `CLIENT_BOT_USERNAME`) — обращения клиентов:

- `/start` или `/new` → имя → контакт (текстом или кнопкой «Поделиться телефоном») → запрос → лид с тегом `telegram`. Лид появляется только после всех трёх ответов.
- Повторная заявка с тем же контактом или именем и запросом всё равно сохраняется и получает тег `возможный дубль`; в истории лида указано, с кем он совпал. Клиенту бот о дублях не сообщает — решение принимает менеджер.
- `/cancel` отменяет заявку. После заявки обычные сообщения попадают в переписку клиента. Здесь же счета, статусы заявки и рассылки (`/payments`, `/subscribe`, `/unsubscribe`, `/stop`).
- Каждое новое обращение приходит уведомлением **всей команде** в бот команды; сообщения клиента — ответственному, а если его нет, всей команде.

**Бот команды** (`TELEGRAM_BOT_TOKEN`) — CRM для сотрудников:

- При регистрации в CRM обязателен свой Telegram; уже зарегистрированные указывают его в «Команда и роли» → профиль. Сотрудник пишет боту `/start` с этого аккаунта — Telegram привязывается к профилю. Без юзернейма в Telegram — кнопка «Привязать по одноразовой ссылке» в профиле. Посторонним бот отвечает ссылкой на клиентского бота.
- Меню: лиды по этапам, по тегам, поиск (любой текст, телефон в любом формате), карточка лида; смена этапа, добавление и удаление тегов, «Взять себе», новый лид с проверкой дублей, «Мои задачи» с отметкой выполнения, ответ клиенту. Права те же, что в CRM: наблюдатель только смотрит.
- Все уведомления CRM дублируются в Telegram: новые обращения и сообщения клиентов, назначение ответственным, новые и переданные задачи, напоминания, общий чат и личные сообщения, подтверждённые оплаты. Себе о собственных действиях уведомления не приходят.

Общее:

- Менеджер отвечает клиенту через **Мессенджер → Клиенты** или кнопкой «Ответить» в боте команды. Ответ сохраняется в очереди и отправляется обычно в пределах 5 секунд.
- Ошибки сети оставляют сообщение в очереди для повтора. При постоянной ошибке Telegram (400/403) сообщение помечается «Не доставлено».
- Вложения не поддерживаются. Один токен — один экземпляр процесса, без webhook.
- При сбое между фактической отправкой и подтверждением в SQLite исходящее сообщение может повториться; входящие обновления дедуплицируются.

## Данные и обновление

Схема обновляется автоматически, существующие лиды сохраняются. Перед переходом с v1 в этом окружении создана резервная копия `data/before-crm-v2.sqlite`. Рабочая база — `data/crm.sqlite`. Старые лиды Telegram без сохранённого chat_id нельзя автоматически связать с перепиской: новые заявки уже сохраняют эту связь. Тестовые аккаунты и лиды в рабочую базу не добавляются.

Демо-наполнение: `node scripts/seed-demo.mjs` (или `docker exec jumpads-crm node scripts/seed-demo.mjs` после копирования скрипта в контейнер) добавляет 5 сотрудников с разными ролями, 12 лидов на всех этапах, задачи и историю. Запускается один раз на базу; у демо-сотрудников случайные несохраняемые пароли — войти под ними нельзя.

Для резервной копии остановите приложение и скопируйте весь каталог данных либо используйте SQLite backup/VACUUM INTO. Не копируйте только основной файл работающей базы с WAL.

## Проверки

```powershell
npm test
```

Проверки охватывают регистрацию и роли, отзыв сессии, подтверждение дублей и идемпотентность, ограничения задач, приватность личных сообщений, Telegram-очередь, напоминания и восстановление данных после перезапуска.

`node scripts/verify-ui.mjs` — браузерный сценарий. Нужны Playwright и установленный Edge. Можно указать `PLAYWRIGHT_PATH` (модуль Playwright) и `BROWSER_CHANNEL=chrome`. Проверка использует временную базу в памяти; скриншоты сохраняются в `artifacts/`.

## Публикация

Рабочая версия: **https://lushik.online** — VPS в Москве (Debian, Docker), один экземпляр процесса, база SQLite в томе `jumpads-data`.

- `deploy/Caddyfile` — Caddy принимает HTTPS (сертификаты Let's Encrypt выпускаются и продлеваются сами), `www` и `http` перенаправляет на `https://lushik.online`, остальное проксирует в CRM на `127.0.0.1:3000`.
- `deploy/deploy.sh` — пересобирает образ из `/opt/jumpads` и пересоздаёт контейнер; данные сохраняются. Запускать после изменения кода или `.env`: Docker читает `.env` только при создании контейнера.
- Контейнер CRM работает в сети сервера (`--network host`): с этого VPS Telegram доступен только по IPv6, которого нет в обычной сети Docker. Порт 3000 слушается только на `127.0.0.1`.
- `TRUST_PROXY=true` (CRM за Caddy), `APP_PUBLIC_URL=https://lushik.online` (уведомления Т-Банка), `TEST_ROLE_SELECTION=true` (тестовое задание: роль выбирается свободно).
- Т-Банк использует сертификат НУЦ Минцифры: корень `certs/russian_trusted_root_ca.pem` (официальный файл с gu-st.ru) подключён только к запросам в банк. Если уведомление банка не дошло, CRM раз в минуту сама запрашивает статус неоплаченных счетов.

Обновление кода: скопировать `src`, `public`, `certs`, `package.json`, `Dockerfile` в `/opt/jumpads` и выполнить `/opt/jumpads/deploy.sh`.

`tools/crm_tunnel.py` — прежний вариант публикации с ПК через SSH-туннель localhost.run; сейчас не используется. Личный Telegram-аккаунт (MTProto), вложения, приглашения, сброс пароля, произвольные этапы воронки и автоматические резервные копии остаются за пределами текущей версии.

## Структура

- `src/store.js` — лиды и базовое хранилище.
- `src/crm.js` — миграции, аккаунты, роли, задачи, напоминания и сообщения.
- `src/bot.js` — транспорт Telegram: опрос обновлений и очередь отправки для обоих ботов.
- `src/staff-bot.js` — бот команды: лиды, теги, этапы, задачи, ответы клиентам.
- `src/client-bot.js` — клиентский бот: пошаговая заявка, переписка, счета, рассылки.
- `src/server.js` — HTTP API и проверки прав.
- `public/` — интерфейс.
- `test/` — интеграционные проверки.
- `docs/submission.md` — черновик для сдачи.

## Автоматизации и фильтры канбана

Добавлены конструктор «событие → условия → действия», паузы, повторная проверка условий, ручной запуск, шаблоны и журнал. События связывают лиды, задачи, оплату и клиентского бота; шаги меняют карточку, создают задачи и отправляют уведомления. Канбан получил сохранённые личные фильтры и перетаскивание. Интерфейс обновлён в привычной для Bitrix24 логике CRM.

Инструкция и границы версии: [docs/automations-and-kanban.md](docs/automations-and-kanban.md). Код: `src/automations.js`, `public/workflow.js`. Проверки: `test/automations.test.js`, `scripts/verify-automation-ui.mjs`.
