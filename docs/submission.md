# Мини-CRM для заявок агентства

Черновик для сдачи. Живая CRM: https://lushik.online. Клиентский бот для заявок: @JumpADSClients_bot, бот команды: @JumpADSCRM_bot. Перед отправкой — пройти приёмку ниже с телефона, переписать текст своими словами и добавить ссылку на резюме.

## Набросок продукта

Менеджер небольшого агентства получает запросы из переписок и вручную переносит их в таблицы. На этом этапе теряются контакты и контекст задачи. Мини-CRM собирает заявки в одном месте: имя, контакт, запрос, источник, статус и теги. Основной пользователь — менеджер или владелец агентства; клиент общается только с Telegram-ботом.

Контур работы:

```text
Клиент → Telegram-бот → имя / контакт / запрос
                                 ↓
                         Node.js → SQLite
                                 ↑
Менеджер → CRM в браузере → ручной ввод / теги / статусы
                                 ↓
                         Поиск и фильтрация
```

MVP включает обязательные пункты 1, 3 и 4: сбор заявки ботом, ручное добавление и теги с фильтром. Каждая заявка бота автоматически получает тег `telegram`. Менеджер добавляет тематические теги, например `лендинг` и `приоритет`, затем выбирает нужную группу. Статусы «Новый», «В работе», «Предложение», «Сделка», «Закрыт» помогают отличать ещё не разобранные обращения.

Для трёхдневного проекта выбран один процесс Node.js и SQLite: не нужна отдельная служба базы данных, меньше настроек для запуска. Данные хранятся на постоянном диске. Диалог и смещение обновлений Telegram сохраняются в транзакции вместе с лидом: повторная доставка одного сообщения не создаёт дубль. Временный сбой отправки ответа обрабатывается через очередь повторов. В CRM реализована регистрация по юзернейму и паролю, индивидуальные сессии и роли администратора, менеджера и наблюдателя. По дополнительному запросу включён тестовый выбор собственной роли; при обычном использовании его можно отключить.

Дополнительно реализованы компания и сумма сделки, ответственный, заметки, история изменений, архив лидов, воронка, задачи с исполнителем и сроком, напоминания, общий и личные чаты команды и текстовая переписка через бота. Дубли по контакту или совпадению имени и запроса требуют подтверждения при ручном вводе в CRM. Заявка из бота сохраняется всегда и при совпадении получает тег `возможный дубль`: клиенту не задаются вопросы о внутренних данных CRM, а повторное обращение не теряется. За пределами текущей версии: вложения, автоматические рассылки, расширенная аналитика, приглашения участников и подключение обычного Telegram.

Необязательный пункт 2 предполагается реализовать отдельным адаптером Telegram Client API (MTProto). Пользователь подключает аккаунт через телефон, код и 2FA; сессия хранится зашифрованно на сервере. Адаптер слушает входящие личные сообщения, исключает исходящие и служебные события, дедуплицирует их по аккаунту/чату/сообщению и создаёт лид с источником `telegram_account`. Первое сообщение даёт запрос и доступный контакт; неизвестное имя уточняется менеджером. Последующие сообщения обновляют контекст существующего открытого лида. Нужны интерфейс выбора чатов, отключение аккаунта и отдельные проверки восстановления соединения. В текущей реализации такого подключения нет.

## Короткий разбор

Работа началась с извлечения требований из DOCX и проверки пустой папки проекта. Затем были реализованы хранилище, диалог бота, HTTP API с авторизацией и браузерный интерфейс. После этого написаны интеграционные проверки, включая восстановление диалога после перезапуска и защиту от повторного Telegram update. Проверка через Playwright обнаружила горизонтальное переполнение на телефоне: таблица была заменена мобильным представлением карточками, после чего браузерный сценарий прошёл.

В реализации использован Codex: разбор ТЗ, написание кода, тестов и документации. Навык DOCX помог выбрать способ чтения документа; UI/UX-навык использован для базовых требований к формам, контрасту и адаптивности. Telegram Bot API и Node.js SQLite сверялись с официальной документацией. Исходные запросы пользователя: «Начни выполнение тз» и «продолжай»; затем пользователь запросил регистрацию, подтверждение дублей, задачи, напоминания, роли, воронку и оба вида мессенджера. Описание решений в этом черновике подготовлено ИИ; автору задания нужно проверить его и добавить собственные наблюдения. Скриншоты промптов не создавались.

На текущем этапе выполнены автоматические проверки API, прав доступа, приватности личных сообщений, напоминаний и обработчика бота. Браузерный сценарий проверяет регистрацию, отказ и согласие на дубль, воронку, задачи, напоминания, чаты, смену собственной роли и вход/выход на desktop/mobile. Внешний Telegram API в интеграционных тестах заменён тестовыми сообщениями; это не подтверждает работу реального бота. Следующий шаг — подключить токен, развернуть приложение на постоянном хостинге и пройти сценарий по живой ссылке.

За дополнительную неделю: подключение личного Telegram, приглашения и сброс пароля, вложения, пагинация, резервные копии и мониторинг ошибок. При росте нагрузки — переход на PostgreSQL и отдельный процесс приёма Telegram-событий.

Материалы реализации: [Telegram Bot API](https://core.telegram.org/bots/api), [Node.js SQLite](https://nodejs.org/api/sqlite.html).


## Расширение: тестовая оплата и клиентский бот

По дополнительному запросу добавлены второй Telegram-бот для клиентов и тестовый эквайринг Т-Банка. Участники второго бота становятся лидами; сохраняются доступные Telegram-данные, собственный контакт и история сообщений. Менеджер создаёт счёт в карточке, бот получает ссылку, а подтверждённое банковское уведомление переводит лид в «Оплачено» и проставляет отдельный признак оплаты. Доступны одно напоминание о неоплаченном счёте и рассылки подписавшимся клиентам с предпросмотром и подтверждением. Полный путь проверен изолированными тестами; реальные ключи банка и токен второго бота ещё не подключены. Настройка описана в `payments-and-client-bot.md`.

## Расширение: два бота — клиенты и команда

Заявки клиентов принимает клиентский бот (@JumpADSClients_bot): имя → контакт → запрос → лид с тегом `telegram` в CRM. О каждом новом обращении сразу узнаёт вся команда. Основной бот (@JumpADSCRM_bot) стал рабочим инструментом сотрудников: лиды по этапам и тегам, поиск, карточка, новый лид, теги, этапы, задачи и ответ клиенту. В него же приходят все уведомления CRM. Сотрудник указывает свой Telegram при регистрации или в профиле и пишет боту `/start`. Посторонним бот команды отвечает ссылкой на клиентского бота.
