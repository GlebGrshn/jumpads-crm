# Доступ после переноса на VPS

Исправление от 3 октября 2026 года.

## Причина страницы ожидания

CRM уже работала на VPS `185.22.154.170`: `/health` отвечал, оба бота подключались. Google DNS и Cloudflare DNS возвращали этот адрес для `lushik.online`. Однако DNS на пользовательском ПК через интерфейс Happ/Xray возвращал прежний хостинг `37.140.192.62`. Очистка DNS-кэша Windows не изменила результат. Старый хостинг отдавал статическую страницу «Jumpads CRM переехала» с обновлением раз в минуту; такое обновление не меняет ответ DNS.

`www.lushik.online` на том же ПК уже разрешался в адрес нового VPS, но Caddy перенаправлял его обратно на `lushik.online`, возвращая пользователя на старую страницу.

## Исправление

- `deploy/Caddyfile` обслуживает CRM на обоих HTTPS-адресах. Редирект `www` на основной домен удалён. Конфигурация проверена командой `caddy validate`, применена через `caddy reload` без перезапуска CRM и ботов.
- На прежнем хостинге заменён только `/www/lushik.online/public/index.html`: теперь это `deploy/legacy-entry.html`, который сразу открывает `https://www.lushik.online/?entry=vps`. Есть переход через JavaScript, meta refresh и обычная ссылка. Параметр даёт новый URL вместо ранее закэшированного постоянного редиректа `/`.
- DNS-записи, VPN и настройки других сайтов не менялись. На ПК не запускается второй экземпляр CRM с боевыми токенами.

Не возвращать редирект `www` → `lushik.online`, пока старый хостинг переводит посетителей на `www`: при устаревшем DNS это замкнёт переход. Оба адреса используют один процесс и одну базу. Cookie сессии привязаны к адресу, поэтому при смене адреса может потребоваться войти повторно. Банковский `APP_PUBLIC_URL` остаётся `https://lushik.online`.

## Проверка

В Edge с этого ПК открытие `https://lushik.online/` привело к `https://www.lushik.online/?entry=vps`; появилась форма входа. Ошибок JavaScript не было, `/health` отвечал `ok: true`. Повторная проверка подтвердила состояние `connected` обоих ботов. Перенаправление проверено на реальном сайте без создания пользователей, лидов или сообщений.

Для посетителя, у которого браузер ещё показывает прежнюю вкладку, достаточно открыть [рабочую CRM](https://www.lushik.online/?entry=vps) или обновить страницу.

Старая конфигурация сохранена на VPS в `/opt/jumpads/Caddyfile.before-www-fix`, прежняя страница — локально в `backups/legacy-entry-before-www-fix.html` (не публикуется в Git). Возврат обоих файлов вернёт и исходную проблему доступа.
